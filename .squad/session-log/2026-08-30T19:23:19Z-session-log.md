## Problem Statement

Contract validation stages (primary agent, supervisor review, alpha review) were receiving the global default model, not the explicitly configured function-specific models (`analysis`, `supervisor`, `alpha`). This created inconsistency with normal watchlist execution, which correctly used function-specific models.

**Impact:** Validation decisions could use wrong model despite configuration.

## Root Cause

`AgentRunner._get_client(model, function_id)` resolved function-specific **providers** (via `function_llms[function_id]`) but fell back to global default **model** when `model=None`, even if `function_id` had a configured model.

## Solution Architecture

### Three-Tier Model Resolution

```python
def _get_client(self, model=None, function_id=None):
    deployment = (
        model                                      # 1. Explicit caller override
        or self._function_models.get(function_id)  # 2. Function-specific config (NEW)
        or self._default_model                     # 3. Global default fallback
    )
    # ... provider resolution follows existing pattern
```

### Infrastructure Components

1. **Storage:** `AgentRunner._function_models: Dict[str, str]` from `function_models=` parameter
2. **Updates:** `AgentRunner.set_function_models(values)` for live reload
3. **Generation:** `Config.function_model_deployments()` creates dict from config
4. **Bootstrap:** `main.py` and `web/app.py` initialize and update function models
