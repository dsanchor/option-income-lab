### Livingston (Persistence & Integration Engineer) — G3 Seam Revision (Escalation Assignment)

**Time:** 2026-08-18 (post-rejection escalation)  
**Input:** Basher's defect escalation (D1-D5), Danny's G0 contract, Linus's frozen merge module, Rusty's initial code as reference baseline.  
**Charter task:** Fix D1-D5, own full seam between pure merge and storage/lifecycle, ensure data round-trip fidelity and production concurrency correctness.

**Authorized scope:** options_chain_store.py (full), options_chain_cache.py (hydration/serving/locking), new integration test file. Frozen: merge, providers, filters, watchdog, schema description.

**D1-D5 fixes:**

**D1/D2 — CAS reconciliation:** Rusty's code called `merge_prior(stored_shard, want_shard)` on already-merged chains (function misuse — meant for "apply live sources to prior", not "blend two past-merged chains"). Fix: `_reconcile_bucket` performs contract-level union — contract on one side kept as-is; on both sides, kept wholesale from whichever has newer quote_asof (never blended, never re-derived). Monotone, safe under CAS retry.

**D3 — Hydration horizon:** Served days-old expirations (not pruned), lacked top-level symbol/timestamp/underlying_price documented in schema. Fix: `_hydrate_into_memory` applies same-day America/New_York `prune_by_expiration`, restores top-level fields from most-recent shard, stamps stale-eligible.

**D4 — Locking concurrency:** Single `threading.RLock` on event-loop thread froze all requests when held. Reentrancy let same-loop coroutines collide (lost update). Fix: (1) task-level memoization (`_inflight_refresh`) for same-loop reuse via asyncio.shield; (2) per-symbol OS locks with blocking acquire offloaded to executor — waiting never blocks calling loop.

**D5 — Change-detection hash:** Included volatile _meta.last_seen (advanced every cycle regardless of data), never converged. Fix: hash only market-observable fields + underlying_price via `_hashable_contract` view — unchanged data hashes identically, skips unnecessary rewrites.

**P1 Sync-in-Async Bridge Deadlock (post-approval follow-up):** Danny approved D1-D5, then opened P1: D4's per-symbol OS lock made pre-existing `get_or_load` sync-in-async bridge able to self-deadlock when called synchronously from async context (web/app.py:3249 inside async `api_activity_chat`). Fix: branch on loop state — no loop: block normally; loop running: kick off background refresh + raise OptionsChainNotReadyError (compatible with app's existing graceful degradation). Result: 5 new additive tests, all passing, 3x determinism verified.

**Schema:** v2→v3 (pre-approved), added underlying_price to shard body; lazy on-read normalization ensures v2 shards hydrate fine.
