### D1-D5 Defects & Fixes

**D1/D2 — Store composition bug:**  
CAS conflict reconciliation was calling `merge_prior(stored_shard, want_shard)`, misusing a function designed for "apply live sources to prior" on an "already-merged past merged chain" — the composition, not the function, was broken. Fix: store now performs verbatim contract-level union (`_reconcile_bucket`) — a contract on one side is kept as-is; on both sides, kept *wholesale* from whichever has more-recent `_meta.last_seen`/`quote_asof` (never blended, never re-derived). Monotone, safe under CAS retry.

**D3 — Hydration serving horizon:**  
Hydrated data was never pruned (so days-old expirations were served as candidates) and lacked top-level `symbol`/`timestamp`/`underlying_price` documented in schema. `_hydrate_into_memory` now applies same-day America/New_York `prune_by_expiration`, restores missing top-level fields from most-recent shard, stamps entry stale-eligible so next `is_stale()` schedules real background refresh.

**D4 — Locking concurrency:**  
Single `threading.RLock` on event-loop thread froze every request whenever a scheduler-thread refresh held it; reentrancy let same-loop coroutines both run full cycles (lost update). Replaced with: (1) task-level memoization (`_inflight_refresh: Dict[str, asyncio.Task]`) — same-loop caller reuses/awaits exact same task via `asyncio.shield`; (2) per-symbol OS lock (`_symbol_os_locks: Dict[str, threading.Lock]`, plain non-reentrant) whose blocking `acquire()` is always offloaded to executor via `loop.run_in_executor` — waiting on cross-thread hold never blocks calling loop. `refresh_all` untouched — funnels through `refresh()`, fix applies transitively.

**D5 — Change-detection dead code:**  
Old hash included entire `_meta` blob, but `_meta.last_seen` legitimately force-advances every cycle a contract is listed (even with zero value changes) — hash never converged in production. Fixed by hashing `_hashable_contract` view excluding volatile `last_seen`/`quote_asof` (keeps all market-observable fields + `underlying_price`) — unchanged market data now hashes identically, skipping unnecessary rewrites.

**Schema:** `schema_version` 2→3 (pre-approved), added `underlying_price` to shard body. `hydrate()` reconstructs top-level `timestamp`/`underlying_price` from most-recently-`updated_at` shard; legacy v2 shards hydrate fine without it.

### P1 Sync-in-Async Bridge Deadlock (Post-Approval Follow-up)

Danny approved D1-D5, then opened P1: D4's per-symbol OS lock made `get_or_load`'s *pre-existing* sync-in-async bridge able to self-deadlock when called synchronously from async context (reachable from `web/app.py:3249`, especially on cold miss).

**Root cause:** `get_or_load` did `ThreadPoolExecutor().submit(self._sync_refresh).result(timeout=120)` on calling loop's thread — a blocking wait. `_sync_refresh` eventually awaits `loop.run_in_executor(None, os_lock.acquire)`. If the lock was held by a task needing the same *frozen* loop to finish and release, self-deadlock.

**Fix:** `get_or_load` branches on whether loop is running:
- No running loop (genuine sync caller): unchanged, blocks that thread, returns real data.
- Loop running: reuse non-blocking `_schedule_background_refresh` to kick off background refresh (or no-op if in-flight), immediately raise `OptionsChainNotReadyError` (compatible with `web/app.py`'s existing graceful degradation). No blocking wait = no deadlock.
