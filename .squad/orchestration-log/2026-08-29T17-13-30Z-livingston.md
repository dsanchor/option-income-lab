### 3. Options Screener: Concurrency Seam Layer

**Directive:** `.squad/decisions/inbox/copilot-options-screener-approved.md`  
**Implementation:** `backend/src/options_chain_cache.py`

**Defect Found During Gate:**
Event-loop-blocking Cosmos I/O ran directly on the async event loop inside `_build_screener_symbol_inputs` (cache warming seam layer), freezing concurrent requests and breaking endpoint responsiveness under moderate symbol count.

**Fix Applied:**
- Added `trigger_swr` kwarg to `get_or_hydrate` method (Cosmos-blocking operation)
- When `trigger_swr=True`, wrap blocking I/O in `run_in_executor` to offload to thread pool
- Screener endpoint calls `get_or_hydrate(..., trigger_swr=True)` for cache warming, unblocking the event loop
- Non-screener callers (direct symbol detail, etc.) can omit or pass `trigger_swr=False` as needed

**Validation:**
- 4 concurrency tests (`test_options_screener_endpoint.py`): all passing
  - Multiple simultaneous screener requests no longer serialize on Cosmos I/O
  - Chain warming throughput preserved
- Full backend suite: 1758 passed (no regressions in broader persistence layer)
