### 2. Full Execution Traces for Supervisor & Alpha

**Date:** 2026-08-29  
**Directive:** `.squad/decisions/inbox/copilot-supervisor-alpha-traces.md`  
**Status:** ACCEPTED design, implementation in progress

**Key Design Rulings:**
- Separate trace documents in the *same* `agent_traces` container (no new container)
- New `phase` literals: `"supervisor"`, `"alpha"` (pure domain concept; `agent_type` remains the primary decision's type)
- Unified `run_id` across all phases within one decision cycle (uuid4 minted once at cycle start)
- Causal `parent_trace_id` linkage (flat, one-hop, points to the phase document id that precedes this one; `roll` -> `assessment`; `supervisor`/`alpha` -> final phase's trace)
- Full-fidelity capture: prompt, raw response, parsed output, model, duration, error string
- Reuse of existing `write_agent_trace` contract (90-day TTL, `enabled_types` toggle unchanged)
- Zero UI changes required (existing `phase` rendering already dynamic, no hardcoded allowlist)

**Implementation Ownership:**
- `agent_runner.py` (trace instrumentation): Rusty
- `cosmos_db.py` (write contract, projection update): Livingston
- Frontend type extension: Rusty
- Adversarial test suite: Basher

**Design Rationale in Decisions:**
- Gap confirmed at source: `_run_supervisor_review`/`_run_alpha_review` never call `_record_trace` today; full context only in console/logs, not persisted
- `run_id` (not activity id) chosen for correlation to keep trace layer independent and available even on exception paths
- `parent_trace_id` deliberately precise (points to *decision* phase, not run root) — Supervisor/Alpha review the *decision made*, and when a roll occurs that decision is the roll's, not the assessment's
- `agent_type` unmapped in trace (internal `_AGENT_TYPE_MAP` remap for instruction selection does not leak into trace or gating) — one checkbox in Settings covers primary + reviews
