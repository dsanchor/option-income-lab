### Outcome 3: Livingston D1-D5 Persistence Seam Revision (Livingston, 2026-08-18)

**Status:** ✅ Implemented — all defects fixed, P1 sync-in-async bridge fix added post-approval.

**Escalation:** Initial Rusty implementation rejection (D1-D5) prompted casting of Livingston as new Persistence & Integration Engineer with explicit revision directive and frozen baselines.

**D1-D5 Defects & Fixes:**

**D1/D2 — Store CAS reconciliation:** Was calling `merge_prior(stored_shard, want_shard)` on already-merged chains (function misuse). Fix: `_reconcile_bucket` performs contract-level union — contract on one side kept as-is; on both sides, kept wholesale from whichever has newer quote_asof (never blended, never re-derived). Monotone, safe under CAS retry.

**D3 — Hydration horizon:** Served days-old expirations, lacked top-level symbol/timestamp/underlying_price. Fix: `_hydrate_into_memory` now applies same-day America/New_York `prune_by_expiration`, restores top-level fields from most-recent shard, stamps stale-eligible for next background refresh.

**D4 — Locking concurrency:** Single RLock on event-loop thread froze all requests; reentrancy allowed same-loop coroutines to collide (lost update). Fix: (1) task-level memoization (`_inflight_refresh: Dict[str, asyncio.Task]`) for same-loop reuse; (2) per-symbol OS locks (`_symbol_os_locks`) with blocking acquire offloaded to executor — waiting never blocks calling loop.

**D5 — Change-detection:** Hash included volatile _meta.last_seen (advanced every cycle even if data unchanged), never converged. Fix: `_hashable_contract` view hashes only market-observable fields + underlying_price — unchanged data hashes identically, skips unnecessary rewrites.

**Schema:** v2→v3 (pre-approved), added underlying_price to shard body; legacy v2 shards hydrate fine.

**P1 Sync-in-Async Bridge Deadlock (Post-approval):** D4's per-symbol OS lock made pre-existing `get_or_load` sync-in-async bridge self-deadlock under contention. Fix: Branch on loop state — no loop (sync caller): block normally; loop running: kick off background refresh, raise OptionsChainNotReadyError (compatible with app's graceful degradation). Result: 5 new additive tests in test_options_chain_cache.py (39 total, all passing, 3x determinism).
